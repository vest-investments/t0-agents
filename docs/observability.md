# Observability

## Automatic tracking

Every call to `run_agent` captures tracking data in the returned `AgentResult`:

| Field | Type | Description |
|-------|------|-------------|
| `episode_id` | `str \| None` | Groups all turns of a single agent run. Generated by TensorZero on the first inference. |
| `inference_ids` | `list[str]` | One ID per turn. Use to attach per-turn feedback. |
| `turns` | `int` | Number of inference turns consumed. |
| `response_source` | `"text" \| "thought"` | Whether the final response came from `Text` or `Thought` blocks. |

## Glow: tool-call observability via `run.events()`

Glow agents stream typed events, and `run.events(<selector>)` is the per-tool
observability surface. It is streaming-only by construction: `await run` /
`run.result()` drives the non-streaming loop, which has no per-tool event
channel. Import selectors from `t0_agents.glow`.

### Per-tool-call signals on `ToolResultEvent`

Each executed tool call yields a `ToolResultEvent`. The signals are computed
once in the shared executor, so both agent loops produce them identically:

| Field | Type | Description |
|-------|------|-------------|
| `is_error` | `bool` | Typed error flag — from the dispatch error branch or `CallToolResult.is_error`, not a sniff of `result` for an `"ERROR:"` prefix. |
| `duration_ms` | `float \| None` | Wall-clock of the `call_tool` round-trip. `None` when the call never dispatched (hallucinated name / invalid JSON arguments). |
| `server` | `str \| None` | Namespace of the owning mounted server. `None` for an unprefixed (`prefix=False`) or single local mount — the same attribution rule `statuses()` uses. |
| `structured` | `dict \| None` | The tool's raw `structured_content`, when it returned one. |

```python
from t0_agents.glow import ToolResult

async for tr in agent("...").events(ToolResult):
    print(tr.name, tr.server, tr.duration_ms, tr.is_error)

# Narrow with .where(...), or project with .map(...):
async for tr in agent("...").events(ToolResult.where(lambda r: r.is_error)):
    log.warning("tool %s failed: %s", tr.name, tr.result)
```

### A minimal per-call observer

No middleware framework needed — the events already carry name, server,
duration, and the typed error flag. A short consumer logs every call:

```python
import logging

from t0_agents.glow import ToolResult

log = logging.getLogger("tool_calls")

async def observe(run) -> None:
    async for tr in run.events(ToolResult):
        log.info(
            "tool=%s server=%s duration_ms=%s error=%s",
            tr.name, tr.server, tr.duration_ms, tr.is_error,
        )
```

### Elicitation events

`ElicitationRequestedEvent` / `ElicitationResolvedEvent` are in the
`AgentEvent` union (selectors `ElicitationRequested` / `ElicitationResolved`),
carry a shared correlation `id`, and project onto the public wire's
`elicitation_request` / `elicitation_resolved` frames. They are emitted
in-stream by conversation-scoped elicitation
([Multi-tenant apps](glow/multi-tenant.md)): pass the conversation an
`ElicitationForwarder` and the event `id` **is** the forwarder's
`elicitation_id` — the same id an out-of-band resolver answers — so both
paths describe one elicitation; a bare handler gets a glow-minted id.
A consumer wiring both must still render the prompt from **one** path.
App-scoped handlers (no conversation identity) do not emit — their
elicitations stay out-of-band only.

### Public tool inventory

`await app.tools()` returns the merged, namespace-prefixed inventory — the
public replacement for reaching into `app._owned_client`.
`app.tools(refresh=True)` drops the per-server TTL caches and re-lists.

### Status hints and the `server=None` caveat

`run.statuses()` interleaves opaque `Status(text, server, tool)` hints,
decomposing each tool name against the App's mounted namespaces. A tool from a
`prefix=False` mount has no namespace prefix to decompose, so its `server` is
`None` — the same caveat as `ToolResultEvent.server`.

## Structured logging

The agent loop logs to the `t0_agents.mcp.loop` logger using Python's standard `logging` module.

| Level | Content |
|-------|---------|
| INFO | Loop start (function name, max_turns, tool count), per-turn content types and IDs, thought-only fallback, loop completion (turn count, episode_id) |
| DEBUG | Tool dispatch (names and count), tool results (truncated to 200 chars), Thought text (truncated to 500 chars), per-tool timing in ms |
| WARNING | Max turns exceeded, recoverable inference errors (e.g. malformed tool names rejected by TensorZero) |
| ERROR | Tool name not in schema, invalid JSON arguments, ToolError, McpError, unexpected exceptions |

## Enabling logging

```python
import logging
logging.basicConfig(level=logging.INFO, format="%(name)s %(levelname)s %(message)s")
# For per-tool timing and result details:
logging.getLogger("t0_agents.mcp.loop").setLevel(logging.DEBUG)
```

## TensorZero Feedback API

After `run_agent` returns, use the TensorZero SDK to send feedback. Feedback links to episodes or individual inferences and is stored in ClickHouse for analytics and optimization.

```python
# Boolean (episode-level): was the task successful?
await t0.feedback(episode_id=result.episode_id, metric_name="task_success", value=True)

# Float (inference-level): quality score for a specific turn
await t0.feedback(inference_id=result.inference_ids[-1], metric_name="quality_score", value=0.9)

# Comment: free-form text for human review
await t0.feedback(episode_id=result.episode_id, metric_name="comment", value="Correct result.")
```

Metric names (except `comment` and `demonstration`) must be declared in `tensorzero.toml`:

```toml
[metrics.task_success]
type = "boolean"
level = "episode"
optimize = "max"

[metrics.quality_score]
type = "float"
level = "inference"
optimize = "max"
```

## The dryrun caveat

When `dryrun=True`, inference IDs are generated but **not stored** in ClickHouse. Any `t0.feedback()` call targeting those IDs will fail with HTTP 400. Use `dryrun=False` (the default) for feedback workflows.

## ClickHouse analytics

TensorZero stores all inferences in ClickHouse, including `additional_tools` schemas and tool call/result content. Queryable dimensions: inference latency, tool call frequency, error rates, episode-level success rates, and model variant comparison.

## Examples

### Easy: enable INFO logging, observe output

```python
import logging
logging.basicConfig(level=logging.INFO, format="%(name)s %(levelname)s %(message)s")
# Output:
# t0_agents.mcp.loop INFO Agent loop started: function=agent, max_turns=20, tools=3
# t0_agents.mcp.loop INFO Turn 1: inference_id=..., content_types=['ToolCall']
# t0_agents.mcp.loop INFO Agent loop completed: turns=2, episode_id=...
```

### Intermediate: capture IDs and send boolean feedback

```python
async def run_with_feedback(t0, client, query: str) -> None:
    result = await run_agent(t0, client, query, "agent", dryrun=False)
    print(f"Episode: {result.episode_id}, Turns: {result.turns}")

    # Send task-level feedback
    fb = await t0.feedback(
        episode_id=result.episode_id,
        metric_name="task_success",
        value=True,
    )
    print(f"Feedback stored: {fb.feedback_id}")
```

### Advanced: full feedback pipeline with ClickHouse query

```python
async def full_pipeline(t0, client, query: str) -> None:
    result = await run_agent(t0, client, query, "agent", dryrun=False)
    await t0.feedback(episode_id=result.episode_id, metric_name="task_success", value=True)
    await t0.feedback(inference_id=result.inference_ids[-1], metric_name="quality_score", value=0.95)
    await t0.feedback(episode_id=result.episode_id, metric_name="comment",
                      value=f"Completed in {result.turns} turns.")
```

```sql
SELECT i.episode_id, count(*) AS turns, avg(f.value) AS avg_quality
FROM inference i
LEFT JOIN feedback f ON f.inference_id = i.id AND f.metric_name = 'quality_score'
GROUP BY i.episode_id ORDER BY avg_quality DESC LIMIT 20;
```
