## 1. Structure of `mcp.types.Tool`

In the MCP protocol, a tool is represented with `mcp.types.Tool`. The FastMCP docs show its structure explicitly in the "Before" example (low-level SDK):

```python
import mcp.types as types

types.Tool(
    name="add",
    description="Add two numbers",
    inputSchema={
        "type": "object",
        "properties": {
            "a": {"type": "number"},
            "b": {"type": "number"},
        },
        "required": ["a", "b"],
    },
)
```

The three fields that matter for the adapter are:

| Field          | Type     | Description                                       |
|----------------|----------|---------------------------------------------------|
| `name`         | `str`    | Tool name                                         |
| `description`  | `str \| None` | Tool description (may be `None`)             |
| `inputSchema`  | `dict`   | JSON Schema of the input parameters               |

> **Source:** `getting-started.md` > "Tools" > "Before" example (low-level SDK).
> Original URL: https://gofastmcp.com/getting-started/upgrading/from-low-level-sdk.md

`mcp.types.Tool` is a Pydantic model, so it supports `.model_dump()` to convert it to a dictionary.

## 2. How FastMCP generates `name`, `description`, and `inputSchema`

FastMCP automatically derives these three fields from your Python function:

```python
from fastmcp import FastMCP

mcp = FastMCP("math")

@mcp.tool
def add(a: float, b: float) -> float:
    """Add two numbers"""
    return a + b
```

The derivation rules are:

- **`name`**: taken from the function name (`add`), unless `name=` is passed to the decorator.
- **`description`**: taken from the function's **docstring** (`"Add two numbers"`). If `description=` is passed to the decorator, the docstring is ignored.
- **`inputSchema`**: automatically generated from the **type annotations** of the parameters.

> **Source:** `servers-tools.md` > main section and "Decorator Arguments".
> Original URL: https://gofastmcp.com/servers/tools.md

### Decorator with explicit overrides

```python
@mcp.tool(
    name="find_products",
    description="Search the product catalog with optional category filtering.",
    tags={"catalog", "search"},
)
def search_products_implementation(query: str, category: str | None = None) -> list[dict]:
    """Internal function description (ignored if description is provided above)."""
    ...
```

### Decorator `description` parameter

```
description (str | None):
    Provides the description exposed via MCP.
    If set, the function's docstring is ignored for this purpose.
```

> **Source:** `servers-tools.md` > "@tool Decorator Arguments" > `description`.

### Supported type annotations

FastMCP supports all types that Pydantic supports as fields:

| Type Annotation   | Example                                   | Description                                  |
|:------------------|:------------------------------------------|:---------------------------------------------|
| Basic types       | `int`, `float`, `str`, `bool`             | Simple scalar values                         |
| Binary data       | `bytes`                                   | Binary content                               |
| Date and Time     | `datetime`, `date`, `timedelta`           | ISO format strings                           |
| Collection types  | `list[str]`, `dict[str, int]`, `set[int]` | Collections                                  |
| Optional types    | `float \| None`, `Optional[float]`        | May be null/omitted                          |
| Union types       | `str \| int`, `Union[str, int]`           | Multiple types                               |
| Constrained types | `Literal["A", "B"]`, `Enum`               | Specific allowed values                      |
| Paths             | `Path`                                    | Auto-converted from strings                  |
| UUIDs             | `UUID`                                    | Auto-converted from strings                  |
| Pydantic models   | `UserData`                                | Complex structured data with validation      |

> **Source:** `servers-tools.md` > "Type Annotations".

### Example schema generated from a Pydantic model

```python
from dataclasses import dataclass

@dataclass
class Person:
    name: str
    age: int
    email: str

@mcp.tool
def get_user_profile(user_id: str) -> Person:
    """Get a user's profile information."""
    ...
```

The `inputSchema` generated for the **input parameters** would be:

```json
{
  "type": "object",
  "properties": {
    "user_id": {"type": "string"}
  },
  "required": ["user_id"]
}
```

> **Source:** `servers-tools.md` > "Typed Models" and schema generation examples.

### Example inputSchema with a Pydantic model as a parameter

When an **input parameter** uses a complex Pydantic model, FastMCP generates a full JSON Schema:

```python
@mcp.tool
def calculate_tax(amount: float, rate: float = 0.1) -> dict:
    """Calculate tax on an amount."""
    return {"amount": amount, "tax": amount * rate, "total": amount * (1 + rate)}
```

Generated schema:

```json
{
  "type": "object",
  "properties": {
    "amount": {"type": "number"},
    "rate": {"type": "number", "default": 0.1}
  },
  "required": ["amount"]
}
```

> **Source:** `development.md` > inline snapshots example with `calculate_tax`.

## 3. Client: `list_tools()` and its return value

The FastMCP `Client` has two methods for listing tools:

### `list_tools()` — the one you will use

```python
list_tools(self: Client, max_pages: int = AUTO_PAGINATION_MAX_PAGES) -> list[mcp.types.Tool]
```

Retrieves **all** available tools from the server. Handles pagination automatically.

**Returns:** `list[mcp.types.Tool]` — a list of `mcp.types.Tool` objects.

**Raises:**
- `RuntimeError`: if the page limit is reached before pagination completes.
- `McpError`: if the request results in `TimeoutError | JSONRPCError`.

### `list_tools_mcp()` — manual pagination control

```python
list_tools_mcp(self: Client) -> mcp.types.ListToolsResult
```

Returns the full MCP protocol object. Use this only if you need manual pagination control with the cursor.

> **Source:** `python-sdk-fastmcp-client-mixins-tools.md` > `list_tools` and `list_tools_mcp`.
> Original URL: https://gofastmcp.com/python-sdk/fastmcp-client-mixins-tools.md

### Full Client usage

```python
import asyncio
from fastmcp import Client

client = Client("http://localhost:8000/mcp")

async def main():
    async with client:
        tools = await client.list_tools()
        for tool in tools:
            print(tool.name, tool.description)

asyncio.run(main())
```

**Important:** All client operations require the `async with` context manager.

> **Source:** `clients.md` > "Creating a Client".
> Original URL: https://gofastmcp.com/clients/overview.md

### Transport options

```python
from fastmcp import Client, FastMCP

# In-memory (testing)
server = FastMCP("TestServer")
client = Client(server)

# HTTP
client = Client("https://example.com/mcp")

# Local Python script (STDIO)
client = Client("my_mcp_server.py")
```

> **Source:** `clients.md` > "Choosing a Transport".

## 4. Client: `call_tool()` and tool execution

```python
call_tool(
    self: Client,
    name: str,
    arguments: dict[str, Any] | None = None
) -> CallToolResult | ToolTask
```

Calls a tool on the server. Unlike `call_tool_mcp`, this method **raises `ToolError`** if the tool returns an error.

**Args:**
- `name`: tool name.
- `arguments`: dictionary of arguments. Defaults to `None`.
- `timeout`: timeout for the call.
- `meta`: additional metadata.

**Returns:** `CallToolResult` (or `ToolTask` if `task=True`).

**Raises:**
- `ToolError`: if the tool returns an error.
- `McpError`: if there is a `TimeoutError | JSONRPCError`.
- `RuntimeError`: if not connected.

### `call_tool_mcp()` — raw result

```python
call_tool_mcp(
    self: Client,
    name: str,
    arguments: dict[str, Any],
    ...
) -> mcp.types.CallToolResult
```

Returns the raw `CallToolResult` from the protocol. **Does not raise an exception** if the tool returns an error (you must check `isError`).

> **Source:** `python-sdk-fastmcp-client-mixins-tools.md` > `call_tool` and `call_tool_mcp`.

## 5. `model_dump()` and field access

Each `mcp.types.Tool` returned by `list_tools()` is a Pydantic model. For your adapter, you can access the fields in two ways:

### Direct attribute access

```python
tools = await client.list_tools()
for tool in tools:
    name = tool.name              # str
    description = tool.description  # str | None
    input_schema = tool.inputSchema  # dict
```

### Conversion to dict with `model_dump()`

```python
tools = await client.list_tools()
mcp_tools = [tool.model_dump() for tool in tools]

# Each dict has the keys:
# tool["name"]         -> str
# tool["description"]  -> str | None
# tool["inputSchema"]  -> dict (JSON Schema)
```

The mapping to TensorZero (from the official MCP → T0 example) is:

```python
t0_tools = [
    {
        "name": tool["name"],
        "description": tool["description"],  # ⚠️ may be None
        "parameters": tool["inputSchema"],
    }
    for tool in mcp_tools
]
```

> **Note:** `inputSchema` on the MCP side maps to `parameters` on the TensorZero side.
> This is documented in your attached TensorZero guide.

## 6. Schemas generated by Pydantic and `$ref` dereferencing

### Automatic dereferencing

FastMCP **automatically dereferences** `$ref` entries in tool schemas for compatibility with MCP clients that do not support JSON Schema references:

> FastMCP automatically dereferences `$ref` entries in tool schemas to ensure compatibility with MCP clients that don't fully support JSON Schema references (e.g., VS Code Copilot, Claude Desktop). This means complex Pydantic models with shared types are inlined in the schema rather than using `$defs` references.
>
> Dereferencing happens at serve-time via middleware, so your schemas are stored with `$ref` intact and only inlined when sent to clients.

This is **good for your adapter**: when you obtain the `inputSchema` via `list_tools()`, the `$ref` entries should already be resolved.

If you want to disable it (not recommended for your use case):

```python
mcp = FastMCP("my-server", dereference_schemas=False)
```

> **Source:** `servers-tools.md` > note on `$ref` dereferencing.

### `compress_schema` function (reference)

If you need to process schemas manually, this utility exists:

```python
from fastmcp.utilities.json_schema import compress_schema

compress_schema(
    schema: dict,
    prune_params: list[str] | None = None,
    prune_additional_properties: bool = False,
    prune_titles: bool = False,
    dereference: bool = False,
)
```

> **Source:** `python-sdk-fastmcp-utilities-json_schema.md` > `compress_schema`.

### `dereference_refs` function (reference)

```python
from fastmcp.utilities.json_schema import dereference_refs

resolved = dereference_refs(schema)
```

Resolves all local `$ref` entries by inlining their definitions. Only processes local refs (`#/...`). Remote URIs are removed for security (SSRF prevention).

> **Source:** `python-sdk-fastmcp-utilities-json_schema.md` > `dereference_refs`.

## 7. Special case: `description=None`

### When it occurs in FastMCP

- If a function **has no docstring** and no `description=` is passed to the decorator, the `description` field of `mcp.types.Tool` will be `None`.
- The decorator parameter is `description: str | None`.

```python
@mcp.tool
def my_tool_without_docs(x: int) -> int:
    return x * 2
# -> tool.description will be None
```

### Impact on the adapter (F1.6)

In the native TensorZero API (`POST /inference`), `description` is **required** and must be a string. This means you must convert `None` to `""`:

```python
t0_tools = [
    {
        "name": tool["name"],
        "description": tool["description"] or "",  # None -> ""
        "parameters": tool["inputSchema"],
    }
    for tool in mcp_tools
]
```

> **TensorZero requirement source:** your attached document, section 1.
> **FastMCP behavior source:** `servers-tools.md` > "@tool Decorator Arguments" > `description` type `str | None`.

## 8. Testing the adapter

### In-memory testing (recommended)

FastMCP provides in-memory testing without needing to deploy the server:

```python
import pytest
from fastmcp import FastMCP, Client

@pytest.fixture
def test_server():
    server = FastMCP("TestServer")

    @server.tool
    def greet(name: str) -> str:
        """Greet someone."""
        return f"Hello, {name}!"

    @server.tool
    def no_description_tool(x: int) -> int:
        return x * 2  # No docstring -> description=None

    return server

async def test_list_tools_returns_valid_structure(test_server):
    async with Client(test_server) as client:
        tools = await client.list_tools()

        for tool in tools:
            assert hasattr(tool, 'name')
            assert hasattr(tool, 'description')
            assert hasattr(tool, 'inputSchema')
            assert isinstance(tool.name, str)
            assert isinstance(tool.inputSchema, dict)
            # description may be str or None
            assert tool.description is None or isinstance(tool.description, str)

async def test_tool_with_none_description(test_server):
    async with Client(test_server) as client:
        tools = await client.list_tools()
        no_desc = [t for t in tools if t.name == "no_description_tool"]
        assert len(no_desc) == 1
        assert no_desc[0].description is None  # or could be ""

async def test_adapter_conversion(test_server):
    async with Client(test_server) as client:
        tools = await client.list_tools()
        mcp_tools = [tool.model_dump() for tool in tools]

        t0_tools = [
            {
                "name": tool["name"],
                "description": tool["description"] or "",
                "parameters": tool["inputSchema"],
            }
            for tool in mcp_tools
        ]

        for t0_tool in t0_tools:
            assert isinstance(t0_tool["name"], str)
            assert isinstance(t0_tool["description"], str)  # never None
            assert isinstance(t0_tool["parameters"], dict)
            assert "type" in t0_tool["parameters"]  # must be JSON Schema

async def test_call_tool(test_server):
    async with Client(test_server) as client:
        result = await client.call_tool("greet", {"name": "World"})
        assert result.data == "Hello, World!"
```

### Testing prerequisites

```bash
pip install pytest-asyncio
```

```toml
# pyproject.toml
[tool.pytest.ini_options]
asyncio_mode = "auto"
```

> **Source:** `servers-testing.md` and `development.md` > "Testing" and "In-Memory Testing".
> Original URL: https://gofastmcp.com/servers/testing.md

### Testing with Pydantic models as parameters (F1.5)

```python
from pydantic import BaseModel

@pytest.fixture
def server_with_pydantic():
    server = FastMCP("PydanticTest")

    class SearchParams(BaseModel):
        query: str
        limit: int = 10
        filters: dict[str, str] | None = None

    @server.tool
    def search(params: SearchParams) -> list[dict]:
        """Search with complex params."""
        return [{"result": params.query}]

    return server

async def test_pydantic_schema_is_valid_json_schema(server_with_pydantic):
    async with Client(server_with_pydantic) as client:
        tools = await client.list_tools()
        tool = tools[0]

        schema = tool.inputSchema
        assert schema["type"] == "object"
        assert "properties" in schema
        # The schema generated by Pydantic must be valid JSON Schema
```

## 9. Checklist by Phase 1 item

### F1.1 — `list_tools()` returns objects with valid `.name`, `.description`, `.inputSchema`

**What to verify on the FastMCP side:**
- `Client.list_tools()` returns `list[mcp.types.Tool]`.
- Each object has `.name` (str), `.description` (str | None), `.inputSchema` (dict).
- The `inputSchema` is always a JSON Schema with `"type": "object"` at the root.

**Sources:**
- `python-sdk-fastmcp-client-mixins-tools.md` > `list_tools`
- `getting-started.md` > `types.Tool` example
- `servers-tools.md` > schema generation

---

### F1.2 — The adapter converts `list[mcp.types.Tool]` → `list[dict]` with keys `name`, `description`, `parameters`

**Adapter implementation:**

```python
async def convert_fastmcp_tools_to_t0(client: Client) -> list[dict]:
    """Converts FastMCP tools to TensorZero format."""
    tools = await client.list_tools()
    mcp_tools = [tool.model_dump() for tool in tools]

    return [
        {
            "name": tool["name"],
            "description": tool["description"] or "",  # None -> "" (F1.6)
            "parameters": tool["inputSchema"],          # inputSchema -> parameters
        }
        for tool in mcp_tools
    ]
```

**Critical mapping:**
- `tool["inputSchema"]` → `"parameters"` (NOT `"inputSchema"`)
- `tool["description"]` → must be a string, never `None`

**Sources:**
- Your attached TensorZero guide, section 2 (official MCP → T0 example)
- `python-sdk-fastmcp-client-mixins-tools.md`

---

### F1.3 — T0 accepts the converted `additional_tools` without error

**What to verify on the FastMCP side:**
- That the schemas in `inputSchema` are valid JSON Schemas.
- That `$ref` entries are resolved (FastMCP does this automatically at serve-time).
- That there are no extra fields that T0 does not expect.

**Potential issues:**
- `model_dump()` may include additional fields from `mcp.types.Tool` (such as `annotations`, `meta`, `icons`). When building the dict for T0, only take `name`, `description`, `parameters`.

**Source:** `servers-tools.md` > note on `$ref` dereferencing.

---

### F1.4 — With `tool_choice="required"`, always returns a `ToolCall`

**FastMCP side:** Does not apply directly (this is T0/LLM configuration).

**But verify that:** the tools are passed correctly so the LLM "sees" them:
```python
response = await t0.inference(
    function_name="...",
    input={"messages": messages},
    additional_tools=t0_tools,
    tool_choice="required",
)
```

**Source:** Your attached TensorZero guide, section 5.

### F1.5 — Tools with Pydantic models generate schemas accepted by T0

**What to verify on the FastMCP side:**
- Schemas generated from Pydantic models are valid JSON Schemas.
- `$ref` entries are resolved automatically by the dereferencing middleware.
- The schema always has `"type": "object"` at the root.

**Example generated schema:**

```json
{
  "type": "object",
  "properties": {
    "amount": {"type": "number"},
    "rate": {"type": "number", "default": 0.1}
  },
  "required": ["amount"]
}
```

**Potential edge cases:**
- Schemas with `$defs` and `$ref` entries that do not get resolved (if the server has `dereference_schemas=False`).
- Schemas from self-referential (recursive) models. FastMCP has `resolve_root_ref()` for this.

**Sources:**
- `servers-tools.md` > "Type Annotations", "Output Schemas"
- `python-sdk-fastmcp-utilities-json_schema.md` > `dereference_refs`, `resolve_root_ref`
- `development.md` > inline snapshots example with schemas

---

### F1.6 — Tools with `description=None` are converted with `""` without error in T0

**When it occurs in FastMCP:**
- Function with no docstring and no `description=` in the decorator.
- `@mcp.tool` allows `description: str | None`.

**Fix in the adapter:**
```python
"description": tool["description"] or "",
```

**Sources:**
- `servers-tools.md` > `description` type `str | None`
- Your attached TensorZero guide, section 1 (description is required in the native API)

## Appendix: FastMCP constraints to keep in mind

1. **`*args` and `**kwargs` are not supported** in tool functions. FastMCP requires a complete parameter schema.
   > (source: `servers-tools.md`)

2. **`$ref` dereferencing** happens at serve-time via middleware. If you access the server directly (without going through the MCP protocol), you may get schemas with unresolved `$ref` entries.
   > (source: `servers-tools.md`)

3. **The Client's `call_tool()` raises `ToolError`** if the tool returns an error. Use `call_tool_mcp()` if you prefer to handle errors manually via `isError`.
   > (source: `python-sdk-fastmcp-client-mixins-tools.md`)

4. **All Client operations require `async with`** for connection lifecycle management.
