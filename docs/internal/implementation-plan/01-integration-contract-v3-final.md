# Integration Contract v3 (FINAL): TensorZero + FastMCP

> **Status**: Verified against both documentations. Ready to implement.
>
> **Changes vs v2**: Corrected exception handling (McpError vs ToolError),
> clarified import paths, added optional parallel execution pattern,
> aligned Client lifecycle with the agent loop.

---

## 1. Objective

Build a Python integration layer that allows an agent based on
**TensorZero** to discover and execute tools exposed by one or more
**FastMCP** servers, so that the LLM can decide which functions to invoke
based on the context of the user's query.

---

## 2. Definitions

| Term | Meaning |
|---|---|
| **T0 Gateway** | TensorZero Gateway instance (Rust, API on `localhost:3000`) |
| **T0 SDK** | `tensorzero` Python package — `AsyncTensorZeroGateway`, `Message`, `Text`, `ToolCall`, `ToolResult` |
| **FastMCP Server** | MCP server built with `fastmcp.FastMCP` |
| **FastMCP Client** | `fastmcp.Client` — high-level client with auto-pagination, `.data`, `ToolError` |
| **Adapter** | Python code that translates between FastMCP ↔ TensorZero formats |
| **Agent Loop** | Cycle `inference → tool calls → execution → result → next inference` |

## 3. Technical Contract

### 3.1 TensorZero Surface (DOCUMENTED AND VERIFIED)

**a) Dynamic tools (`additional_tools`)**

Each tool is a dict passed in `additional_tools` of `t0.inference()`:

```python
{
    "name": str,           # tool name (required)
    "description": str,    # description for the LLM (required)
    "parameters": dict,    # standard JSON Schema for the input (required)
    "strict": bool,        # strict validation (optional, default False)
}
```

The `parameters` field accepts standard JSON Schema (`type: "object"`,
`properties`, `required`, `additionalProperties`). T0 passes this schema to
the LLM provider without processing it. Schemas with dereferenced `$defs` (such
as those generated by FastMCP by default with `dereference_schemas=True`) should
work because T0 forwards them as-is to the provider.

> **⚠️ Scenario to validate (EC-1)**: Schemas with very complex types (deeply nested
> Pydantic models) could cause issues in some LLM providers,
> not in T0 itself. Keep schemas to ≤2 levels of nesting.

(source: gateway-api-reference.md > "additional_tools" > "Function Tools")

**b) Content types in the response**

`response.content` is a list of blocks:

- `Text` — `.text: str`
- `ToolCall` — `.name`, `.raw_name`, `.arguments`, `.raw_arguments`, `.id`
  - `.arguments` can be `null` if the LLM's arguments are invalid JSON
  - `.raw_arguments` always contains the raw string from the LLM

(source: gateway-api-reference.md > Response > Chat Function)

**c) ToolResult — the result MUST be a string**

```python
ToolResult(
    name=str,     # tool name
    result=str,   # result as STRING (required)
    id=str,       # ID of the original tool call
)
```

Serialization strategy:
- If FastMCP `.data` is `str` → use directly
- If FastMCP `.data` is `dict`/`list`/object → `json.dumps(result.data, default=str)`
- Fallback: concatenate `.content[*].text`

(source: gateway-api-reference.md > content block type `tool_result`)
(source: examples/mcp-model-context-protocol/main.py)

**d) Parallel tool calls — all results in ONE single message**

When the LLM returns N `ToolCall` blocks, the N `ToolResult` are packaged in
a SINGLE `Message(role="user", content=[...all_results])`.

(source: examples/mcp-model-context-protocol/main.py)

**e) Episode management**

- First inference: `episode_id=None` → gateway generates one
- Subsequent inferences: reuse `response.episode_id`
- To generate your own: `from tensorzero.util import uuid7`

(source: gateway-guides.md > Episodes)

**f) Tool calling control**

```python
await t0.inference(
    ...,
    tool_choice="auto",           # "none" | "auto" | "required" | {"specific": "name"}
    parallel_tool_calls=True,     # only OpenAI and Fireworks AI support this
    allowed_tools=["tool_a"],     # restricts which tools the LLM can use
)
```

(source: gateway-guides.md > "Customizing the tool calling strategy")

**g) Feedback**

```python
await t0.feedback(
    inference_id=uuid,    # or episode_id=uuid
    metric_name=str,      # defined in tensorzero.toml, or "comment"/"demonstration"
    value=...,            # type depends on the metric
)
```

(source: gateway-api-reference.md > "POST /feedback")


### 3.2 FastMCP Surface (VERIFIED AGAINST DOCUMENTATION)

**a) Tool definition**

```python
from fastmcp import FastMCP

mcp = FastMCP("MyServer")

@mcp.tool
def search(query: str, max_results: int = 10) -> list[dict]:
    """Search the database."""  # docstring → description
    ...
```

- `name` is inferred from the function name
- `description` is inferred from the docstring
- `inputSchema` is generated from type annotations via Pydantic
- Customizable: `@mcp.tool(name=..., description=..., tags=..., timeout=...)`
- Supports Pydantic models, all Pydantic types, `Annotated` for metadata
- `$ref` is automatically dereferenced (`dereference_schemas=True` by default)
- `*args` and `**kwargs` are NOT supported in tools

(source: servers-tools.md > "The @tool Decorator")
(source: servers-tools.md > "Type Annotations")

**b) Transports**

| Transport | Use | How |
|---|---|---|
| **in-memory** | Testing/development | `Client(mcp_instance)` |
| **stdio** | Default, subprocess | `mcp.run()` |
| **HTTP** (Streamable) | Production (recommended) | `mcp.run(transport="http", host="0.0.0.0", port=8000)` |
| **SSE** | Legacy/backward-compat | `mcp.run(transport="sse", ...)` |

(source: deployment.md > "Transport Protocols")

**c) FastMCP Client**

```python
from fastmcp import Client

async with Client(server_or_url) as client:
    tools = await client.list_tools()            # list[mcp.types.Tool]
    result = await client.call_tool(name, args)  # CallToolResult
```

- No need for `mcp.ClientSession` or `StdioServerParameters`
- Accepts: FastMCP instance (in-memory), URL string, path to .py, or config dict
- Automatic auto-pagination in `list_tools()`
- Async context manager is mandatory (`async with`)

(source: clients.md > "The FastMCP Client")

**d) Tool format**

`list_tools()` returns `list[mcp.types.Tool]` with:
- `.name: str`
- `.description: str | None`
- `.inputSchema: dict` (JSON Schema, camelCase)

(source: getting-started.md > "Upgrading from the MCP Low-Level SDK")
(source: python-sdk-fastmcp-client-mixins-tools.md)

**e) Result format**

`call_tool()` returns `CallToolResult` with:
- `.data` — deserialized Python object (PREFERRED, FastMCP exclusive)
- `.content` — `list[ContentBlock]` (MCP standard: TextContent, ImageContent, etc.)
- `.structured_content` — `dict | None`
- `.is_error` — `bool`

Note: FastMCP auto-wraps primitives (`int`, `str`, `bool`) in `{"result": value}`
and the client auto-unwraps them, so `.data` returns the original value.

(source: clients.md > "Calling Tools" > "Structured Results")

**f) Error handling — THREE EXCEPTION TYPES**

```python
from fastmcp.exceptions import ToolError   # tool itself failed
from mcp import McpError                   # timeout, protocol, JSON-RPC
```

| Exception | When raised | Import |
|---|---|---|
| `ToolError` | The tool itself failed (execution error) | `from fastmcp.exceptions import ToolError` |
| `McpError` | Timeout, protocol error, JSONRPCError | `from mcp import McpError` |
| `RuntimeError` | Client not connected | built-in |

Alternative without exceptions: `call_tool(..., raise_on_error=False)` + check `result.is_error`

(source: clients.md > "Error Handling")
(source: python-sdk-fastmcp-client-mixins-tools.md > call_tool Raises)
(source: servers-middleware.md > on_initialize — McpError import path)

**g) Multi-server**

Option A — Server-side with `mount()` + automatic namespacing:
```python
main = FastMCP("Main")
main.mount(weather_server, namespace="weather")  # tools: weather_get_forecast
main.mount(calendar_server, namespace="calendar") # tools: calendar_create_event
```

Option B — Client-side with config dict:
```python
config = {
    "mcpServers": {
        "weather": {"url": "https://weather.example.com/mcp"},
        "calendar": {"command": "python", "args": ["./calendar.py"]}
    }
}
client = Client(config)
# Tools auto-namespaced: weather_get_forecast, calendar_create_event
```

Both options are compatible with T0 — names with prefixes arrive as-is
in `additional_tools` and return identically in `ToolCall.name`.

(source: servers-composition.md > "Composing Servers" + "Namespacing")
(source: clients.md > "Multi-Server Configuration")

**h) Async**

FastMCP is async-first. `Client` is async (`async with`, `await`).
Server tools can be sync (executed in threadpool automatically) or async.
No friction with the T0 SDK, which is also async.

(source: servers-tools.md > "Async Support")

## 4. Data Mapping (DEFINITIVE)

### 4.1 FastMCP Tool → T0 additional_tool

```python
async with Client(server_or_url) as client:
    tools = await client.list_tools()
    t0_tools = [
        {
            "name": tool.name,
            "description": tool.description or "",
            "parameters": tool.inputSchema,
        }
        for tool in tools
    ]
```

### 4.2 T0 ToolCall → FastMCP call_tool

```python
for block in response.content:
    if isinstance(block, ToolCall):
        if block.arguments is None:
            # LLM generated invalid JSON — handle error
            ...
        else:
            result = await client.call_tool(block.name, block.arguments)
```

### 4.3 FastMCP CallToolResult → T0 ToolResult

```python
import json

def serialize_tool_result(result) -> str:
    """Converts CallToolResult.data to string for T0."""
    if result.is_error:
        error_texts = [
            c.text for c in (result.content or []) if hasattr(c, "text")
        ]
        return f"Error: {' '.join(error_texts)}" if error_texts else "Error: unknown tool error"

    if result.data is not None:
        if isinstance(result.data, str):
            return result.data
        return json.dumps(result.data, default=str, ensure_ascii=False)

    # Fallback: concatenate content blocks
    texts = [c.text for c in (result.content or []) if hasattr(c, "text")]
    return "\n".join(texts) if texts else ""

t0_result = ToolResult(
    name=block.name,
    result=serialize_tool_result(mcp_result),
    id=block.id,
)
```

## 6. Critical Scenarios

### EC-1: Complex JSON Schema from Pydantic

FastMCP generates schemas from type annotations. T0 passes them to the LLM unchanged.

**Risk**: Providers may not handle schemas with nested objects 3+ levels deep,
`anyOf`, `oneOf`, or union types.

**Mitigation**: Flat schemas or maximum 2 levels. Validate in F1.5.

### EC-2: `arguments` null due to invalid JSON from the LLM

T0 returns `arguments=null` but `raw_arguments` contains the raw string.

**Mitigation**: Check `block.arguments is not None` before `call_tool()`.
If null, send error as tool result to the LLM so it retries.

### EC-3: Namespacing with `mount()` vs names in T0

With `main.mount(server, namespace="weather")`, names are prefixed:
`get_forecast` → `weather_get_forecast`. T0 will receive ToolCalls with the
prefixed name. The FastMCP Client expects the full name in `call_tool()`.

**Validate**: That `block.name` from the ToolCall matches the name in FastMCP.

### EC-4: Serialization of `.data` for T0

`.data` can be any Python type. T0 expects `result=str`.

**Mitigation**: `json.dumps(data, default=str, ensure_ascii=False)` as the
primary strategy.

### EC-5: Timeout — McpError, not ToolError

When `call_tool(..., timeout=N)` expires, FastMCP raises `McpError` (code
`-32000`), NOT `ToolError`. The agent loop MUST catch both exceptions.

**Mitigation**: `except (ToolError, McpError)` in execute_tool_calls.

(source: servers-tools.md > "Timeouts" — "client receives an MCP error with
code -32000")
(source: python-sdk-fastmcp-client-mixins-tools.md > call_tool Raises:
"McpError: If the tool call requests results in a TimeoutError | JSONRPCError")

### EC-6: Providers that do not support parallel tool calls

Only OpenAI and Fireworks AI support `parallel_tool_calls`.

**Mitigation**: Do not assume parallel tool calls. The loop handles both 1 and N
tool calls in a response.
